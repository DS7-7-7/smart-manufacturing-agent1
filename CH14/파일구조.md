# 3. 14.4 가상 ERP DB 및 Tool 정의

## 3.1 `01_init_db.py` — ERP DB 생성

SQLite 기반의 가상 ERP 데이터베이스를 생성한다.

주요 테이블:

```text
customers
products
inventory
orders
order_items
bom
suppliers
supplier_products
production_orders
purchase_orders
payments
```

---

## 3.2 `02_seed_data.py` — 초기 데이터 입력

실습에 필요한 제조 데이터를 입력한다.

예:

```text
제품
P300 / 신제품

현재 재고
P300 / 100개

BOM
P300

 ├─ PCB × 1
 └─ Case × 1

S001 / Motor
S002 / PCB
S003 / Case
```

## 3.3 `03_erp_models.py` — ERP 데이터 모델

SQLAlchemy를 사용하여 ERP DB의 테이블을 Python 객체로 정의한다.

```text
Customer
Product
Inventory
Order
OrderItem
BOM
Supplier
SupplierProduct
ProductionOrder
PurchaseOrder
Payment
```

ERP 모델의 역할은 **데이터베이스에 저장되는 실제 업무 데이터의 구조를 정의하는 것**이다.

# 4. `04_llm_models.py` — LLM 모델 스키마

LLM이 자연어를 처리하고 Agent Workflow에서 데이터를 전달할 때 사용할 **구조화된 데이터 스키마**를 정의한다.

Pydantic을 사용한다.

```python
class OrderRequest(BaseModel):
    product_name: str
    quantity: int
    priority: str = "normal"


class OrderAnalysis(BaseModel):
    product_id: str
    quantity: int
    is_urgent: bool
    payment_status: str


class InventoryResult(BaseModel):
    product_id: str
    current_stock: int
    available_stock: int
    shortage: int


class OrderDecision(BaseModel):
    action: str
    quantity: int
    reason: str


class PurchaseOrderItem(BaseModel):
    material_id: str
    quantity: int
    supplier_id: str


class PurchaseOrderResult(BaseModel):
    supplier_id: str
    items: list[PurchaseOrderItem]
    status: str
```

## ERP 모델과 LLM 모델의 차이

```text
03_erp_models.py
        ↓
DB에 저장되는 업무 데이터의 스키마

04_llm_models.py
        ↓
LLM Agent가 처리하고 전달하는 데이터의 스키마
```

예를 들어:

```text
사용자
  ↓
"신제품 P300 500개 주문해줘"
  ↓
OrderRequest
  ↓
Order Agent
  ↓
InventoryResult
  ↓
OrderDecision
  ↓
PurchaseOrderResult
  ↓
ERP DB
```

이 구조를 통해 **자연어 → 구조화 데이터 → Tool → ERP 데이터**의 변환 과정을 학습한다.

# 5. `05_erp_tools.py` — ERP Tool 정의

Agent가 ERP 시스템과 상호작용할 수 있도록 Tool을 정의한다.

## 조회 Tool

```text
get_product()
get_inventory()
get_bom()
get_supplier()
get_payment_status()
```

## 업무 처리 Tool

```text
create_order()
create_production_order()
create_purchase_order()
update_order_status()
```

전체 구조:

```text
Order Agent
    │
    │ Tool Calling
    ▼
ERP Tools
    │
    ├── 제품 조회
    ├── 재고 조회
    ├── BOM 조회
    ├── 공급업체 조회
    ├── 생산계획 생성
    └── 구매발주 생성
    │
    ▼
ERP DB
```

# 6. `06_business_rules.py` — 비즈니스 로직

LLM이 임의로 결정해서는 안 되는 **핵심 업무 규칙**을 별도로 구현한다.

주요 규칙:

```text
재고 충분 여부
부족 수량 계산
생산 가능 여부
결제 상태 확인
발주 필요 여부
긴급 주문 처리 조건
```

역할을 다음과 같이 분리한다.

```text
LLM
→ 자연어 이해 및 작업 계획

Business Rules
→ 업무 규칙 및 의사결정

ERP Tools
→ DB 조회 및 데이터 변경
```

# 7. 14.5 자율 주문 처리 Agent

## 7.1 `07_order_agent.py`

LLM을 기반으로 Order Agent를 구현한다.

예시 입력:

```text
신제품 P300 500개 주문해줘.
```

Agent는 필요한 Tool을 선택하고 호출한다.

```text
주문 분석
    ↓
제품 확인
    ↓
재고 조회
    ↓
재고 부족 여부 확인
    ↓
BOM 조회
    ↓
생산 가능량 확인
    ↓
공급업체 확인
    ↓
생산 또는 구매 발주
```

---

## 7.2 `08_workflow.py`

LangGraph를 이용하여 전체 주문 처리 과정을 Workflow로 구성한다.

```text
START
  ↓
주문 분석
  ↓
주문 검증
  ↓
재고 확인
  ↓
재고 충분?
 ┌──────┴──────┐
YES           NO
 │             │
 ▼             ▼
출고        부족량 계산
               ↓
          생산 가능?
          ┌────┴────┐
         YES        NO
          │          │
          ▼          ▼
       생산계획     구매발주
          │          │
          └────┬─────┘
               ▼
              END
```

---

## 7.3 `09_run_agent.py`

실제 사용자가 주문을 입력하고 Agent를 실행한다.

```bash
python 09_run_agent.py
```

실행 예:

```text
주문을 입력하세요:
> 신제품 P300 500개 주문해줘.
```

Agent 실행:

```text
[Agent] 주문 분석
[Tool] get_product()
[Tool] get_inventory()
[Agent] 재고 부족 확인
[Tool] get_bom()
[Agent] 생산 가능량 확인
[Tool] create_production_order()
[Tool] create_purchase_order()

주문 처리가 완료되었습니다.
```

# 8. 14.6 예외 처리

## `10_exception_handler.py`

정상적인 주문뿐만 아니라 실제 업무에서 발생할 수 있는 예외 상황을 처리한다.

## 8.1 부분 결제

```text
결제 상태 확인
      ↓
 ┌────┴─────┐
 ▼          ▼
완납       부분 결제
 │          │
 ▼          ▼
진행      승인 요청
```

부분 결제 상태에서는 Agent가 임의로 생산이나 발주를 실행하지 않고 **승인 요청 또는 주문 보류** 상태로 전환한다.

---

## 8.2 긴급 주문

```text
긴급 주문
   ↓
생산 CAPA 확인
   ↓
납기 충족 가능?
 ┌────┴────┐
 ▼         ▼
YES       NO
 │         │
 ▼         ▼
긴급 생산  관리자 승인
```

이를 통해 Agent의 자율적인 업무 수행과 **비즈니스 규칙 및 승인 절차**를 함께 구현한다.

# 9. `11_api.py` — FastAPI 서비스화

완성된 Agent를 API 서비스로 확장한다.

```text
Client
  ↓
FastAPI
  ↓
Order Agent
  ↓
LangGraph
  ↓
ERP Tools
  ↓
ERP DB
```

예시 API:

```text
POST /orders
```

요청:

```json
{
    "product": "P300",
    "quantity": 500
}
```

이를 통해 콘솔 기반 Agent를 실제 **제조 업무 자동화 API 서비스**로 확장한다.

## 핵심 구조

```text

    ↓
LLM Schema
    ↓
ERP Tool
    ↓

    ↓

    ↓

    ↓

    ↓
```

따라서 제14장에서는 단순히 LLM을 호출하는 것이 아니라,

> **자연어 주문을 입력받아 LLM Agent가 ERP Tool을 호출하고, 비즈니스 규칙에 따라 재고·생산·구매를 판단하여 실제 주문 처리 Workflow를 수행하는 종합 제조 Agent 시스템**

을 완성하는 것을 목표로 한다.
