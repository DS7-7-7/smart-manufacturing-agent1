CH10 실습 코드 안내

 제조 현장의 자재 관리 담당자를 돕는 AI 에이전트
- 사용자가 자연어로 요청하면, 에이전트가 스스로 판단하여
  필요한 도구(재고 조회, 계산 등)를 골라 사용하고 답변한다
- 단순 챗봇과 달리, 여러 단계의 도구를 이어서 사용할 수 있어
  "재고 확인 후 구매 금액 계산" 같은 복합 요청도 자동 처리

 inventory.json      # 가상 재고 DB (부품 5개)
 tools.py            # 에이전트가 쓸 도구 2개 정의
 agent_skeleton.py   # 에이전트 본체 (4대 요소 구현)
 demo_memory.py      # 메모리 데모 시나리오

각 파일 설명

1 inventory.json
    - 가상 부품 5개 (P-2201, P-3105, P-1042, P-5501, P-2210)
    - 재고 / 임계값 / 단가 / 공급사 정보 포함
    - 에이전트가 재고 조회 도구로 이 파일을 읽는다

2 tools.py
    - 에이전트가 사용할 도구 2개 정의
      · calculator      : 사칙연산 계산
      · inventory_lookup: 부품 재고 조회
    - 각 도구는 name / description / run(args) 세 요소로 구성
    - 단독 실행 시 도구가 잘 작동하는지 확인 가능

3 agent_skeleton.py
    - 에이전트 본체 (10장 본문의 4대 요소를 코드로 구현)
      · 프로파일링 → build_system_prompt() 함수
      · 메모리     → Memory 클래스
      · 계획       → parse_action() + 메인 루프
      · 도구       → tools.py 에서 import
    - 작동 흐름:
      사용자 요청 → LLM 판단 → 도구 호출 → 결과 관찰 → 반복 → 최종 답변
    - 최대 5회 반복 (무한 루프 방지)

4 demo_memory.py
    - 메모리의 필요성을 보여주는 데모
    - 3개 연속 요청 시나리오
      · "P-2201 재고 알려줘"
      · "그거 3개 사려면 얼마야?"       ← 앞 대화 참조
      · "임계값 이하면 몇 개 더 필요해?"
    - 메모리가 없으면 이런 대화 불가능

===============================================
실행 순서
===============================================

1) 도구 먼저 테스트 (LLM 없이 확인)
   py tools.py

2) 에이전트에 단일 요청
   py agent_skeleton.py --once "P-2201 재고 알려줘"

3) 도구 2개를 이어 쓰는 요청
   py agent_skeleton.py --once "P-2201 3개 구매 가격은?"

4) 메모리 데모
   py demo_memory.py

5) 자유 실험 (대화형 모드)
   py agent_skeleton.py
